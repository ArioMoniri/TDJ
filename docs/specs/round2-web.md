# Round 2 web spec (apps/web)

Engine (packages/core) already provides: `compose(options, deps, { locked })`, `swapTanda`, `swapTrack`, `applyFeedback(options, Feedback[])`, `ComposeOptions.context` (ComposeContext), `ComposeOptions.overrides` (UserOverrides), `EXPORTERS[fmt](playlist, { includeCortinas })`, `resolveContext`, `BUILTIN_CONTEXT`, `Catalog(songs, profiles, cache, corpus, overrides, trackEnergy)`, `loadCatalog(root, overrides)` returning `raw` + `contextModel` + `corpus`. Knowledge files: data/knowledge/{orchestra_profiles,cortinas,context_factors,reference_playlists,track_energy,reference_sets}.json.

## 1. API
- `POST /api/compose` body `{ ...options, locked?: Tanda[], overrides?: UserOverrides }`. Validate: finite hours 0.5–12, sizes, eras array; return 400 `{ error }` on invalid JSON; never leak stack traces. When `overrides` is present build a per-request `Catalog` from `loaded.raw` (memoise by a hash of overrides, LRU 8).
- `POST /api/swap` `{ playlist, index }` and `POST /api/swap-track` `{ playlist, tandaIndex, trackIndex }`.
- `POST /api/feedback` `{ options, feedback: Feedback[] }` → `{ options }` (applyFeedback) so the client can recompose.
- `POST /api/export` `{ playlist, format, includeCortinas }` using `Object.hasOwn(EXPORTERS, format)`.
- `POST /api/ai/review` and `POST /api/ai/refine`: provider-agnostic. Headers `x-ai-provider` (anthropic|openai|gemini|openrouter), `x-ai-key`, `x-ai-model`. Server module `lib/server/llm.ts` exposes `complete({ provider, key, model, system, user, json?: boolean })`: Anthropic via `@anthropic-ai/sdk`; OpenAI/OpenRouter via `fetch` to `/v1/chat/completions` (OpenRouter base `https://openrouter.ai/api/v1`); Gemini via `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent?key=`. `refine` takes `{ options, playlist, instruction }` (free text like "warmer start, more vals, no Canaro") and must return strict JSON `{ options: Partial<ComposeOptions>, feedback: Feedback[], note: string }` (system prompt lists the allowed keys and Feedback values; parse defensively; fall back to `applyFeedback` keyword matching when parsing fails).
- `GET /api/meta` adds `contextModel` (factors + options with labels/evidence), `referencePlaylists`, `knowledge` summary counts.
- `GET /api/db/export` → the user's overrides as JSON (client-side state really; keep the route for server storage mode). Server storage mode (optional): when `TDJ_DB_TABLE` env is set (DynamoDB via `@aws-sdk/client-dynamodb` + `lib-dynamodb`), `GET/PUT /api/db?user=<id>` persist overrides keyed by a user id from a signed cookie (`TDJ_SECRET`). Without it, the client stores overrides in IndexedDB (idb-keyval) and sends them with each compose.

## 2. Screens
- **Compose**: add "Tonight" context strip (season, weather, room temperature, time, event, crowd level/size, region (defaults from settings.region), holiday, mood, day) as compact selects/chips with the research label + evidence dot; show "applied shifts" summary (energy ±, vals/milonga share, cortina genres). Feedback bar after a set: chips "More energetic", "Calmer", "Warmer start", "Stronger finish", "More vals", "More milongas", "Fewer repeats", "More romantic", "More playful", "Shorter cortinas" → `applyFeedback` then recompose keeping locked tandas; a free-text box "Tell the DJ…" → `/api/ai/refine` (BYOK) → recompose. Locks must survive recompose (send `locked`). Per-track swap (↻ on a track row) via `/api/swap-track`. Show `tanda.reason` as a one-line caption.
- **Listen**: per tanda a "Listen" toggle that (a) if Spotify is connected, resolves tracks with `lib/spotify.resolveTrack` and renders `https://open.spotify.com/embed/track/{id}?theme=0` iframes (height 80, lazy); (b) otherwise shows the matching reference playlist embed for that orchestra from `reference_playlists.json` (`https://open.spotify.com/embed/playlist/{id}`), plus a "Mood check" panel on the result page with the two Aren León tanda playlists. Cortinas: a "Preview cortina" button → Spotify search embed via resolveTrack when connected.
- **Export sheet**: toggle "Include cortinas" (default on) applied to every format and to the Spotify playlist; show the count that will be exported; for Spotify, the playlist description notes "cortinas included/excluded".
- **Database tab** (`/database`): tabs Songs / Orchestras / Cortinas / Rules / Context. Songs: search the index (`/api/search`) and edit year, singer, rhythm, energy, bpm, hidden, spotify uri inline → overrides.songs[id]; add own recording (addedSongs). Orchestras: edit energy, style, phase, notBefore, tier, singer years. Cortinas: add/edit/delete (JSON form). Rules: gap, year spread, sizes, cortina length, mixVocal, trackEnergy overrides. Context: edit factor shifts. Header: "Repo index built <meta.builtAt>, <n> songs; your overrides: <k> changes" with Import JSON / Export JSON / Reset. Storage: IndexedDB by default; "Server storage" badge when `/api/db` is enabled. Every compose sends overrides.
- **Settings**: Spotify (Client ID, connect); AI provider card with provider select (Anthropic / OpenAI / Gemini / OpenRouter), key, model (suggest defaults: claude-sonnet-5-5, gpt-5.2, gemini-3-pro, openrouter/auto), "Test connection" button hitting `/api/ai/review` with a tiny prompt; DJ-app connectors card: Rekordbox / Traktor / Serato / VirtualDJ / Engine DJ with per-app "music folder path" (used to generate real `Location`/`FILE` paths instead of `TDJ/…`), file naming pattern, and a note on how to import each export; region/appearance as before. All in localStorage via the zustand store (`settings.ai = { provider, key, model }`, `settings.djApps = { rekordbox: { folder }, … }`).
- **Guide**: add "What a great set takes into account" (link to docs/ENHANCEMENTS.md section) and "Context factors" explainer rendered from `contextModel` (label, shift, evidence).
