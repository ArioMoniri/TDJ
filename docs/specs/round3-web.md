# Round 3 web spec: night rules, era presets, agent memory

Engine (packages/core) now exports: `NightRules`, `ERA_SETTINGS`, `withEraSettings`, `AgentMemory`, `emptyMemory`, `applyMemory`, `rememberSet`, `rememberFeedback`, `addNote`, `summarizeMemory`; `Playlist.opening` (Cumparsita before the first tanda), `Playlist.breaks` ({ afterTanda, minutes, label }), `Tanda.note` ("Vals de cumpleaños", "ends with its own La Cumparsita"). `compose()` applies `ERA_SETTINGS[eras[0]]` under the user's explicit options and reads `options.rules`.

## UI
1. **Era presets**: when the user picks an era, show a one-line "Era defaults applied: 3-track tandas · mixed vocal/instrumental · short matched cortinas" (from `ERA_SETTINGS[era].notes`) and set the controls to those defaults (pattern, sizes, shape, cortina style/length, repeat gap) unless the user has pinned a control (pin icon per control, stored in options as `pinned: string[]` client-side only). Add "Reset to era defaults".
2. **Night rules** section on Compose (inset grouped list, below Tonight): toggles/selects for `openWithCumparsita`, `cumparsitaCount` (1 Europe / 2 Buenos Aires), `birthdayValsAt` (off / position slider 10–90 %), `showBreakAt` + `showBreakMinutes`, `ultimaRule`, `openerRule`, `puglieseOnce`, `colourTanda`, `mixedMilongaVals`, `cortinaBeforeCumparsita`. Defaults come from the era preset. Rules travel in `options.rules` on every compose/feedback/refine call.
3. **Result**: render `playlist.opening` as an "Opening" card before tanda 1, `breaks` as a "Show / break · 20 min" divider after the given tanda, and tanda `note` as a badge (birthday vals, own Cumparsita). Set list export already includes opening (kind "closing", tanda 0); show breaks in the set list and CSV as a row.
4. **Memory** (what the agents remember): store `AgentMemory` in the user database (IndexedDB key `tdj-memory`, server mode via /api/db alongside overrides). On every compose → `rememberSet`; on feedback chips / refine → `rememberFeedback`; "Mark as liked/disliked" on the result header; a "Memory" tab in /database listing notes (add/edit/delete, source dj/assistant), set history, feedback history and learned preferences with a "Forget" button each and "Clear memory". Compose applies `applyMemory(options, memory)` (memory under explicit options) and shows "Using what you taught me: energetic floor, shorter cortinas" when preferences apply. `/api/ai/review` and `/api/ai/refine` receive `memory` in the body and include `summarizeMemory(memory)` in the system prompt; refine may return `note` which is stored via `addNote(memory, note, "assistant")`.
5. **Settings**: a "Memory" row with the storage mode and a switch "Let the assistant learn from my feedback".
6. Tests: e2e for rules (open with Cumparsita shows the Opening card; Buenos Aires double closes with two), era switch applies defaults, memory persists a note after reload and the review prompt body contains it (stub provider error path is fine).
